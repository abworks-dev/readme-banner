# pixel 像素风横幅预设设计

状态：拟议方案，尚未接入正式 CLI；已补充独立本地组合原型。2026-11-05。

本文记录设计与研究边界，不改现有 ASCII 预设或主 CLI 的依赖。图片转 ASCII、正面遮罩与像素样张以独立示例提供，不能视作已注册的 CLI 能力。补充调研见[工具组合报告](pixel-toolchain-research.md)；可对比[早期组合原型](../examples/pixel-prototype/README.md)与后续的[细像素 / 中文宽幅样例](../examples/pixel-game-vfx/README.md)。

## 1. 结论

对外预设名采用 **`pixel`**，中文为“像素风”；`pixelfx` 仅是内部可选的**特效引擎**，不是横幅排版器，也不是任意图片的像素画生成器。不把引擎品牌写进公共配置，方便以后更换素材、字体和编码器。

建议关系：

- `preset`：渲染体系，现有 `ascii`，新增 `pixel`。
- `layout`：内容如何排布，如文字左、主视觉右。
- `theme`：深浅两套语义配色，不等于某个特效。
- `fx`：经过筛选的上游特效及受限参数，不把每个效果注册为一个顶层预设。
- `motion`：静态、循环；首版不开放任意时间线编辑。
- `export`：静态/动态资产及 README 引用，与效果实现解耦。

目标不是“把 244 个游戏特效都放进 README”，而是“让仓库用一份配置生成清晰、克制、可复现的像素风品牌横幅”。

## 2. 已核实的上游能力与限制

本节最初依据源码和文档阅读。随后在独立示例中实际运行了固定提交的 energy-core 与 PNG/APNG/GIF 导出；这只验证单个组合，不代表所有 244 个效果或正式 CLI 已经实现。当前项目依赖未变。

| 项目 | 已核实内容 | 对本项目的影响 |
| --- | --- | --- |
| 版本 | 当前读取的清单为 `pixelfx@0.3.0`，Node >=18，ESM | 接入时锁定提交/依赖内容，而非浮动 main；本项目继续 Node >=22 |
| 效果 | 文档列出 244 个、21 类；每个效果包含尺寸、锚点、时长、是否循环等元数据 | 建立适用于横幅的小型白名单，不能只根据名字接入 |
| 渲染 | `createFrame`、`createFx`、`composite`；帧分为 `color` 与加色 `light` | 直接在 Node 中合成像素，不必为核心渲染启动浏览器 |
| 时间 | 纯函数 `draw(p,t,o)`，或有状态 `create(o)`；运行时将模拟细分到 120Hz 或更细 | 首版优先纯函数循环；有状态效果需要固定步进、重置和预热规则 |
| 随机性 | 约定使用 seed，禁止 Math.random / Date | 固定 seed 是必要条件，不是整条导出管线确定性的充分条件 |
| 导出 | 上游提供 PNG 精灵表及 JSON；GIF/MP4 工具调用 ffmpeg | 精灵表不能直接在 README 中播放；APNG 编码是我们需要补的能力 |
| 字体 | 内核只有 mini 3×5、big 5×7 及有限字形；缺字会跳过绘制 | 需要缺字校验、长标题布局；不能声称已支持中文像素字 |
| 许可 | 代码/特效 MIT，含第三方署名；gallery 中 Patch Pixel 字体不在该 MIT 范围内 | 保留许可与 NOTICE；不直接搬用画廊字体 |

尤其注意：上游 `composite(..., null)` 把加色光烘焙为带 alpha 的颜色，注释明确说这主要在深色背景上呈现类似加色的效果。因此不能只导出一份透明图，期待它在 GitHub 黑白背景上都正确；应分别在主题背景上合成浅色与深色版本。

## 3. 像素风还缺哪些东西

### A. 真正的横幅构图

第一版固定一个主布局：文字在左、主视觉在右，标题与副标题始终可读，不跟着场景闪烁。

建议逻辑画布 480×160，整数 2 倍导出 960×320；保留边距、文字安全区和特效专属区域。所有素材共用同一逻辑像素网格，位置、缩放均吸附整数。不得把上游 320×180 场景任意拉成长条；应明确选择裁剪、留边或专门改写构图。

GitHub 在窄屏上可能再次缩放图片，所以只能保证生成资产内部网格一致，不能承诺任意显示宽度都严格整数放大。要检查 960、640、375px 显示宽度下的可读性。

### B. 字体、图标与品牌素材

- 标题：可分发的位图字体、测宽、换行/缩小策略、缺字报错；不要悄悄丢字符或改大小写。
- 副标题：首版明确支持字符集；中文需要另选许可证清晰、字形覆盖足够的点阵字体并锁定光栅化方式。
- Logo：默认保持静态。原生像素图优先；普通 PNG 的最近邻缩小只叫像素化，不等于人工绘制的高质量像素画。
- 自定义图片：限定仓库内 PNG，检查解码尺寸、alpha、文件体积；不从配置下载 URL 或执行用户模块。
- 首版不要同时塞入品牌 Logo、角色、能量球、弹窗和飘字；品牌 Logo 与特效主视觉优先二选一。

### C. 材质分层、遮挡与光照

延续此前确认的审美边界：**正面可以扫光，侧面、孔洞、投影不能被同一个扫光无差别提亮。**

建议层序：背景 → 后景效果 → 静态主体/Logo → 正面遮罩内的局部效果 → 前景粒子 → 不受光照污染的文字/UI。

`color/light` 分离不等于自动认识材质。前景粒子、Logo 表面光和地面光分别受控；如果承诺 Logo 阴影保持不变，就不得让未遮罩的全局 light buffer 再次照亮它。

显式 mask 必须与原图同画布，使用相同变换映射到像素网格；计算完扩散/bloom 后，最终光贡献仍乘接收面 mask。孔洞、侧面和投影属于保护区。没有 mask 时默认不执行 Logo 表面扫光，而不是猜测哪些像素是正面。

已有 [ASCII 遮罩示例](../examples/image-to-ascii/front-mask.mjs)可以复用“显式遮罩、保护区测试”的思想，但不能照搬其 ASCII 专用的 24×48 拟合参数和 10×20 字符单元。

### D. 像素主题

保留 terminal / ocean / neon / minimal 四个公共主题 ID，但像素渲染器需要更多语义色：背景、纸面/面板、描边、正面、侧面、投影、文字、强调色，以及由暗到亮的特效色阶。

上游有些效果除主 palette 外还有 metal / grass / smoke 等独立色阶；只替换主 palette 并不意味着整个效果完成换肤。主题需要适配这些角色。浅色版本可能需要更深描边、减少 bloom、提高亮核与背景的边缘对比，不能只是背景反白。

### E. 动画编排与质量控制

- 第一版只支持一个主循环效果，优先无角色、无屏闪、低干扰的效果。
- 优先候选：`scifi/energy-core`、`ice/ice-crystal`、`pickups/gem-spin`。这些是待视觉筛选的候选，不是已经接入或通过验收的模板。
- weather 类经常是 8–12 秒全屏循环，首版不直接作为默认背景；既增加导出体积，也更容易破坏文字安全区。
- 爆炸、暴击数字、角色战斗和全屏转场不作为默认仓库门面。
- 固定 seed、采样率、时长、初始相位与模拟步长。静帧从同一帧序列取 poster，不重新随机生成。
- 第一版使用效果原生循环周期；不要把任意截取的 3 秒强行声明为无缝循环。
- 首尾相邻帧不必完全相同；验收的是跨边界运动与亮度没有异常突变。

### F. README 导出能力

建议静态 PNG 为必备输出，动画优先验证 APNG：它能保留完整颜色/alpha，避免 GIF 256 色量化损伤柔和光照。**APNG 不是上游现成功能，需要新增编码器，并验证实际 GitHub README、图片代理和目标浏览器。**

拟议格式：

| 用途 | 选择 | 说明 |
| --- | --- | --- |
| 静态/回退/减弱动画 | PNG | 默认、体积稳定、无需播放能力 |
| 保真循环 | APNG | 先验证真实 GitHub 链路，再决定是否作为动态默认 |
| 兼容导出 | GIF | APNG 链路不通过时的替代，或后续显式导出；需固定全局调色板 |
| 静态像素矢量 | 可选 SVG | 合并同色像素块后可做；不是首版必需 |
| README 默认动画容器 | 不选逐像素逐帧 SVG | 大量透明渐变、光照和帧组会放大体积，不能照搬 ASCII 导出方式 |
| 游戏资产交换 | PNG sheet + JSON | 可留作调试/扩展，不直接嵌入 README 播放 |

首次接入做一个很小的 APNG 实验，实测 GitHub 渲染、主题选择和 reduced-motion 媒体条件。不能仅凭本地浏览器能播就宣称 GitHub 全链路支持。若媒体条件被净化或代理行为不符合预期，保证静态引用仍可用，并提供显式选择静态/动态的片段。

GIF 不支持直接在文件内读取 prefers-reduced-motion；APNG 也不支持。自动静态切换依赖外部 `<picture>` 的媒体选择，需同样实测。不能把“提供一张静态图”写成“已经自动尊重减弱动画”。

## 4. 推荐生成管线

```text
JSON 配置 + 受限的本地 PNG / mask（可选）
  → schema / 路径 / 字形 / 尺寸 / 预算校验
  → layout：确定标题区、主视觉区、锚点、像素网格
  → theme：分别解析 light / dark 的语义配色与特效色阶
  → pixelfx adapter：加载白名单模块、重置种子和实例
  → timeline：固定时钟，产生连续帧
  → compositor：后景 / 主体 / 遮罩光 / 前景 / 文字
  → 针对实际主题背景合成 RGBA
  → 从序列取 poster；编码 PNG / 动画
  → 资产清单、预览联系表、字节数与内容哈希
  → 生成 README 片段；只有显式 --readme 才更新受管块
```

两个主题必须各自使用新实例，防止 light 渲染结束的模拟状态串到 dark。字体、编码器、压缩选项与元数据都需锁定。`--check` 比较最终字节，不能依赖随机 ID、时间戳或系统字体。

## 5. 对现有架构的最小演进

### 保留

- JSON 配置公共字段与严格校验：[config.ts](../src/config.ts#L18-L39)。
- 预设注册和发现：[registry.ts](../src/registry.ts#L3-L25)。
- 深浅主题模型：[themes.ts](../src/themes.ts#L3-L30)。
- 显式 README 更新、标记幂等、路径预检等现有安全边界。

### 必须调整

1. **多资产结果。** [当前预设接口](../src/types.ts#L35-L46)只返回 SVG 字符串。新增带格式、still/motion 角色、尺寸与字节内容的结果；旧字符串结果通过兼容适配器继续按 SVG 处理。
2. **导出编排。** [当前生成器](../src/generate.ts#L16-L23)固定 SVG 校验、2MB 限制与文件名。改为按实际格式验证、按资产角色命名，并分别控制像素数、帧数、原始内存与压缩体积。
3. **二进制 drift。** [当前写入层](../src/files.ts)以文本为主；PNG/APNG/GIF 应按字节读取、比较、写入，不得当 UTF-8。README 与配置仍使用文本路径。保留全计划预检、链接拒绝与无变化不写入。
4. **片段由资产清单生成。** [当前 README 片段](../src/readme.ts#L10-L20)把扩展名写死为 .svg；应根据主题、格式、静态/动态角色生成来源。
5. **默认 options 属于预设。** [当前 init](../src/cli.ts#L79-L87)无论 preset 都注入 `effect: glint`。新增 pixel 时必须解除这项 ASCII 耦合；非 ASCII 显式拒绝不适用的 `--art` 等参数，不能靠新预设忽略错误键绕过。
6. **安全资源准备。** 当前 RenderContext 没有资产解析器。由编排层安全读取仓库资源并传入已解码数据或受限 resolver；不要让 JSON 提供可执行路径、模块、shader 或 shell 命令。

需要兼容现有 ASCII 配置、默认输出和受管片段；公共 TypeScript 类型若演进，应在版本与发布说明中说明，不宣称所有第三方调用方零修改。

## 6. 拟议配置

下面是设计草案，**当前 CLI 不支持 `pixel` 及这些字段**。

```json
{
  "schemaVersion": 1,
  "preset": "pixel",
  "theme": "ocean",
  "title": "readme-banner",
  "tagline": "One config. Every repository.",
  "outputDir": "assets/banner",
  "options": {
    "layout": "hero-right",
    "seed": 42,
    "pixelScale": 2,
    "fx": {
      "id": "scifi/energy-core",
      "light": 0.45
    },
    "motion": {
      "mode": "loop",
      "fps": 15,
      "posterFrame": 8
    },
    "export": {
      "still": "png",
      "animation": "apng"
    }
  }
}
```

画布由首版布局固定为 480×160，效果周期来自已筛选的 meta；上例 energy-core 原生 2.4 秒，15fps 得到 36 帧。是否适合此采样率与光强必须看实际输出再定，不把示例数字当已验证最佳值。

原生像素 Logo / mask 属于可选品牌输入；首版保持静态，局部表面光作为明确的进阶能力，而非对任意 Logo 自动加光。

拟议必备资产：`banner.light.png`、`banner.dark.png`；动态启用时再产生 `banner.light.apng`、`banner.dark.apng`。预览联系表和调试清单可选。旧 ASCII 仍产生原来的两张 SVG。

## 7. 三视角候选与优先级

这是产品/设计/工程三视角的候选池，不是首版承诺全部实现。

| 视角 | 五个候选方向 |
| --- | --- |
| 产品 | 项目类型对应场景配方；跨仓库品牌统一；静态/动态双交付；一份配置重生成与 check；Skill 先出候选再让用户选择 |
| 设计 | 文字安全区；统一像素网格；可读字体与长标题策略；显式材质遮罩；独立浅深色美术调校 |
| 工程 | 白名单 pixelfx 适配器；确定性时间线；多格式二进制资产接口；最终光照接收面裁剪；帧/像素/体积与 GitHub 嵌入测试 |

优先做以下五项：

| 优先项 | 选择理由 | 待验证假设 |
| --- | --- | --- |
| 1. 单布局场景合成器 | 把“特效贴纸”变成真正的仓库横幅 | 同一布局适合多数项目名，且窄屏仍读得清 |
| 2. 字体与品牌素材管线 | 横幅首先要表达项目身份，不是展示粒子数量 | 有明确可分发字体、字形覆盖与可接受的长标题策略 |
| 3. 分层与显式遮罩 | 避免重现阴影随正面扫光的错误 | 保护区在所有最终编码帧中保持固定，且动画确实可见 |
| 4. PNG + 动画导出 | README 不运行游戏 Canvas/JS，必须先烘焙 | APNG 在实际 GitHub 链路可靠且体积合适，否则改 GIF |
| 5. 可复现配置与 Skill 流程 | 延续本仓库跨项目复用的核心价值 | 固定依赖/时钟/字体/编码器后，跨平台产物稳定 |

## 8. MVP 与暂不做

### 第一步：技术验证

- 一个固定 hero-right 布局；一个候选循环（energy-core）。
- 固定 480×160 网格、15fps 测试采样；分别生成 light/dark 静帧与短动画。
- 验证光照、缺字、体积、循环边界与真实 GitHub 嵌入。
- APNG、GIF 的清晰度和体积用同一段真实帧序列测量，再敲定发布默认。

### 第二步：可复用首版

- 正式 `pixel` 预设、四主题、约 3 个精选候选主视觉。
- 静态标题、副标题，清晰字符集规则；一个布局，不开放自由场景编辑器。
- PNG 静帧必备，动画显式开启；不依赖 ffmpeg 作为基础生成路径的隐式系统条件。
- 更新 init、配置校验、多资产结果、README 片段、--check、Skill 与 CI。

### 后续

- 自定义像素 Logo / PNG 与表面 mask 的正式输入。
- 低干扰天气背景、多个布局、中文像素字体、多效果时间线。
- 更多格式、编辑器、精灵表导出；这些都不阻塞第一版。

不直接全量搬入 244 个效果，不默认启用角色战斗/屏幕震动/暴闪，不把所有普通图片降采样后宣称是高质量像素画，不让生成器自动提交或推送。

## 9. 验收与预算建议

以下是待实测调整的产品预算，不是 GitHub 平台限制：

- 默认 960×320 导出；首版最多一个主效果。
- 首批动画控制在原生约 2–4 秒的已筛选短循环；15fps 起步，建议最多 96 帧。
- 静帧目标不超过 200KB；动画目标不超过 1.5MB/主题，暂定 2MB 硬上限。超限报清楚原因，不静默换格式或降画质。
- 帧、像素及解码输入单独设限；不能只限制压缩后体积。逐帧流式编码或缓存低分辨率帧，避免同时驻留全部放大 RGBA。
- 同配置、同输入连续两次产生一致字节；两个主题独立重置；Windows/Ubuntu 都检查，编码元数据不含时间戳。
- 旧 ASCII 测试、原有横幅与画廊 drift 检查继续通过。
